## T13 · Реанимация квота-хвостов — предложение «Re-run guard: по закону, а не по памяти»

**Мир:** re-run — штатная механика GitHub Actions с жёсткой рамкой: 30 дней после прогона, до 50 re-run'ов; «Re-run failed jobs» перезапускает и зависимые job'ы, использует тот же GITHUB_SHA/GITHUB_REF и привилегии исходного триггерера (docs.github.com «Re-running workflows and jobs»; REST `POST .../rerun-failed-jobs`). Из рамки следует главный мировой закон: **re-run легален только при идемпотентности шагов** — same-SHA гарантирует «тот же чек», но повтор побочных эффектов (пуш/публикация/выгрузка) — уже ложь. Специализированных практик flaky/self-healing вне доков GitHub в этом срезе достать не удалось (названо вслух); рамка доков сама задаёт границу: re-run — механика восстановления, а не лечение причины.

**Своё:** «re-run guard» — реанимация по закону, три проверки перед выстрелом: (1) хвост упавших шагов обязан совпадать с квот-классом (`artifact storage quota|usage limit|rate limit`) — падение по чужой причине не реанимируется молча, а открывает issue с хвостом лога; (2) среди упавших шагов не должно быть side-effect-шагов workflow (upload/push/publish — список читается из YAML); (3) рамка API проверяется кодом (attempt ≤ 50, возраст ≤ 30 дней). Идемпотентность доказывается артефактно: SHA256SUMS двух попыток diff'ятся — пустой diff = «тот же чек» доказан, не рассуждён. Реран пишется в ворклог (Ст. 6). Универсально: guard применим ко всем 133 воркфлоу аккаунта; сингулярно: guard живёт в github-runbook — репе-учителе самого класса реанимации.

**Приёмка:** `conclusion=success && attempt_count>1` живым API на обоих прогонах (bundle-backup, pages); diff чек-сумм попыток пуст; ворклог-запись есть.

## T14 · nous forge — предложение «Факт без тела: артефактная дисциплина и квота-дозиметр»

**Мир:** квота GitHub Free — ровно 500 МБ хранилища Actions (docs.github.com billing), ISO 880 МБ физически не влезает и душит соседей. upload-artifact v4: артефакты иммутабельны и уникальны по имени, retention-days 1–90, условная выгрузка — штатный `if:` на шаге (github.com/actions/upload-artifact; Workflow syntax docs.github.com). Мировой паттерн «факт без тела» — artifact attestations: `subject-digest: sha256:…` пишет provenance в транспаренси-лог, не тратя квоту (docs.github.com «Artifact attestations»; на free — только public).

**Своё:** ① ISO-шаг forge.yml — `if: inputs.auto_publish == true` + `retention-days: 3`; служебный шаг `if: always()` — build-log.txt + SHA256SUMS, retention 14. ② «Факт без тела»: digest ISO печатается шагом в лог и ложится в SHA256SUMS — провенанс живёт в журнале даже когда тела нет (файл-как-API по Ст. 13, ноль новых зависимостей; для приватных реп attestations недоступны — fallback честно в SHA256SUMS). ③ **квота-дозиметр** — эмерджентный ход: weekly-job суммирует `size_in_bytes` артефактов по всем репам живым API и при >400 МБ (80% квоты) открывает issue с таблицей «репа → МБ → что почистить» — «хвост задушенной квоты» становится измеримой метрикой, а не утренним сюрпризом. Универсально: дозиметр закрывает класс проблем всех 133 воркфлоу; сингулярно: выгрузка ISO переведена из класса «штатная» в класс «релизный обряд» с пломбой digest.

**Приёмка:** grep forge.yml: у ISO-шага есть `if` и retention ≤ 3; jq-сумма size_in_bytes < 500 МБ; строка `sha256` присутствует в логе штатного прогона; ubuntu-2404 не деградировал.

## T15 · singulyar перепин — предложение «Живой пин с TTL-пломбой»

**Мир:** мир 2025–2026 сводит «pin + независимая проверка» к in-toto/SLSA: provenance — аттестация subject+digest+builder.id (slsa.dev/spec/v1.0; in-toto attestation framework, CNCF) — заявка ≠ доказательство, верификатор сам измеряет. GitHub в 2025–2026 шёл туда же: workflow lockfiles с пином action'ов на SHA и рекомендацией актуализации ботами (docs.github.com «Locking action dependencies»). Renovate закрепил паттерн «пин протухает» отдельной опцией lockFileMaintenance (docs.renovatebot.com; recreateWhen: always) — периодически пересобирать пин целиком.

**Своё:** ① перепин рантаймом: скрипт берёт `git ls-remote … refs/heads/rumu` сам — пин берётся из факта, не из памяти (Ст. 6: журнал не лжёт — и пин не лжёт). ② оракул-измеритель: oracle-rumu не читает MANIFEST.json как истину — сам делает ls-remote, сверяет с body_pin; success только при совпадении; при совпадении пишет attestation-подобную строку `{subject: rumu@<sha>, checked: дата}` в лог — SLSA-паттерн без инфраструктуры. ③ **TTL-пломба** — эмерджентный ход: оракул обязан падать, если `body_checked` старше 7 дней — протухший пин перестаёт быть тихой аномалией (аналог «двух правд» T09) и становится громким красным. ④ cron-перепин раз в неделю в духе lockFileMaintenance: перепинил → сразу дёрнул оракула — окно рассинхрона закрывается. Универсально: «живой пин + TTL» закрывает класс горячих пинов всего роя (геном cell-swarm — T18); сингулярно: singulyar 1,58 ГБ не трогается вовсе — правится манифест из двух полей.

**Приёмка:** dispatch oracle-rumu → success; `git ls-remote == jq .body_pin`; дата body_checked < 7 дней; бейдж оракула passing; геном-пин singulyar не сломан.

## T16 · polymath-os lint README — предложение «Исключение с маркером: не воевать с генератором»

**Мир:** все три больших линтера сошлись на правиле «сгенерированное исключают, а не правят руками»: Biome 2.x — files.includes с семантикой «последний матчующий выигрывает» + overrides (biomejs.dev/reference/configuration); Prettier — .prettierignore и инлайн-маркеры для «AUTO-GENERATED BY TOOLS» (prettier.io/docs/ignore); ESLint — globalIgnores() (eslint.org). Тренд 2025–2026: исключение из линта — норма, но «молчаливое исключение» — антипаттерн: игнорируемый файл без причины и маркера — чёрный ящик.

**Своё:** вариант (б) карты, доведённый до честности: ① README.md в biome.json через override (`formatter/linter: enabled: false` — гарантированно перекрывает базу по «last matching override wins»). ② **маркер генерированности**: арт-волна обязана писать в шапку README `<!-- generated-file: art-wave; do-not-edit -->`; CI-страж ловит «исключён, но без маркера» — исключение из линта не превращается в молчаливую ложь (Ст. 6). ③ разделение поров: README проверяется своим шагом (markdown-линт в такте генератора), код — biome; формат-ошибка генератора перестаёт блокировать чужие job'ы, но не исчезает из CI. Универсально: приём «исключение с маркером и стражем» применим ко всем генерённым файлам роя (СВОД-HTML, ПУЛЬС, манифесты); сингулярно: биом больше не воюет с волной, а волна платит за свободу маркером.

**Приёмка:** `biome check README.md` → exit 0 (ignored); `biome ci .` зелёный на арте-коммите без ручных правок; маркер в шапке README; страж ловит тестовый файл без маркера.

## T17 · universal-agent манифест — предложение «Манифест свежести: генерится, а не пишется»

**Мир:** чек-сумм-манифесты везде генерятся машиной: GoReleaser генерит checksums.txt в релиз (goreleaser.com); Debian рассылает SHA256SUMS + отсоединённую подпись поверх него (cdimage.debian.org — скачано живьём в срезе); brew bump-formula-pr вычисляет SHA-256 сам, best effort (docs.brew.sh). GitHub закрепил это практикой «Verify release integrity» + Immutable releases (docs.github.com); SLSA — общая рамка: целостность подтверждается provenance, а не рукописным файлом (slsa.dev).

**Своё:** прецедент ci #16 институционализируется, а не чинится руками: ① цель `make manifest-check`: `make manifest && git diff --exit-code -- release/manifest_sha256.txt` — падение с точным приговором «README изменился — пересобери манифест». ② манифест объявлен генерённым: маркер-шапка `# GENERATED by make manifest — do not edit` + страж в CI (ручная правка манифеста = красный). ③ release-режим: на тегах SHA256SUMS генерится по всем upload-артефактам + immutable releases — починка превращается в постоянную гарантию. Эмерджентная связка: манифест целостности = та же пломба, что SEALS.jsonl доктрины, — один канон доказательства на файлы релизов и файлы доктрины. Универсально: рецепт один для всех 41 реп; сингулярно: «устаревший манифест» перестаёт быть классом ошибок — он стал невозможным.

**Приёмка:** check-run manifest-freshness краснеет на правке README без пересборки и зеленеет после `make manifest`; `git grep GENERATED` в манифесте; регрессия test 3.10/3.11/3.12 не деградировала.

## T18 · cell-swarm геном — предложение «Pin-freshness: геном, который сам догоняет тело»

**Мир:** OpenGitOps формулирует принцип Continuously Reconciled (opengitops.dev) — декларация обязана непрерывно догонять факт, иначе перестаёт быть single source of truth. Argo CD — auto-sync/self-heal (argo-cd.readthedocs.io); Flux — reconciliation с записью observed digest в статус ресурса (fluxcd.io). Renovate делает авто-догоняющие пины штатным классом: digest pinning для github-actions + actions.lock + custom regex-менеджер для любых чужих пинов (docs.renovatebot.com).

**Своё:** геном cell-swarm получает reconcile-петлю на файлах-как-API (без сокетов): ① cron-петля pin-freshness (раз в 6 часов): HEAD каждой клетки живым API vs пин в swarm.json; расхождение → PR «genome: chase <репа> <old>→<new>»; авто-merge только при fast-forward и зелёной регрессии — self-heal для генома. ② drift-детектор на каждый PR: таблица «пин → HEAD → behind» в step summary; красный при behind ≥ 10 — PR#5 (клетка agryp) вливается с живым пином, а не с мёртвым. ③ пины пишут статус: рядом с pin — observed_head и checked_at (Flux-паттерн) — дрейф наблюдаем, а не внезапен. ④ grep-страж: пины живут только в swarm.json (`git grep '"pin"' -- ':!swarm.json'` пуст). Универсально: петля покрывает все клетки генома; сингулярно: геном — тот же файл-как-API, что agrypctl: reconcile без единого сокета — Argo на минимализме.

**Приёмка:** `jq '.pin == .observed_head'` для polymath-os; зелёный scheduled-прогон pin-freshness; PR#5 влит с пином = живой HEAD agryp.

## T19 · Vulnerability alerts ×4 — предложение «Иммунитет: включить и замкнуть цепь»

**Мир:** Dependabot alerts — базовый сканер дефолт-ветки по GitHub Advisory Database (docs.github.com); включение — официальные REST-эндпоинты vulnerability-alerts и automated-security-fixes (docs.github.com/rest). OpenSSF Scorecard проверка Dependency-Update-Tool (риск High) прямо оговаривает: «enabled ≠ merged» — без конфига обновлений алерты не превращаются в PR (github.com/ossf/scorecard). Для массового включения GitHub описывает security configurations и security campaigns (docs.github.com «Security at scale»); NIST SSDF требует практики реагирования на уязвимости (csrc.nist.gov). Мировые численные SLA в срезе не подтвердились (CISA недоступна) — SLA ниже свой, названо вслух.

**Своё:** ① идемпотентный enable-скрипт ×4 (markitdown, polymath-gen, rtynbirf, rumu): PUT alerts + PUT fixes + контрольный GET с таблицей «репа → alerts → fixes»; повторный запуск безопасен. ② замкнуть цепь по Scorecard: в те же 4 репы той же волной кладётся dependabot.yml (T20) — иначе алерты без конфига мертвы. ③ **мини-кампания** — эмерджентный ход: weekly-job собирает открытые critical/high старше 7/14 дней и открывает issue «иммунитет просрочен» — самодельный security campaign на чистом Actions, доступный personal-аккаунту; месячный digest идёт в СВОД. Универсально: скрипт применим ко всем 41 репе; сингулярно: иммунитет получает метрику возраста — не «включено/выключено», а «сколько дней алерту».

**Приёмка:** GET vulnerability-alerts и automated-security-fixes — «включено» ×4×2; через сутки: открытых критичных 0 либо issues кампании открыты.

## T20 · dependabot.yml ×16 — предложение «Волновой генератор с приёмкой»

**Мир:** dependabot.yml — конфиг-как-код с палитрой 2025–2026: cooldown (security-обновления без задержки, остальные — 3 дня), groups (меньше PR за счёт группировки minor+patch), open-pull-requests-limit, rebase-strategy (docs.github.com dependabot options reference). Scorecard Dependency-Update-Tool — риск High (16 реп без конфига = измеримый минус). Secure-use guide: workflow lockfile «сильнее SHA-пиннинга», но алерты Actions генерятся только по semver, не по SHA (docs.github.com) — политика пинов должна учитывать обе правды; Dependabot × SHA-пины документально в срезе не подтвердился — названо вслух.

**Своё:** ① волновой генератор с защитой «уже есть — пропуск»: скрипт по списку 16 реп делает GET contents; 404 → создать из шаблона cell65-host одним атомом; 200 → skip + причина в таблицу; артефакт волны — «created N, skipped M». ② умный шаблон: github-actions weekly + groups (minor+patch одним PR) + cooldown 3 дня + limit 5 — меньше шума на 16 репах, security не тормозится. ③ анти-«Invalid workflow file» приёмка: после первого цикла скрипт-аудит — все workflows валидны API'ем, в логах нет Invalid workflow file; отчёт пин-политики (`uses:` либо semver@vN для Dependabot, либо full-SHA с комментарием тега) в step summary. Универсально: генератор закрывает класс «волна конфигов на флот» для любых будущих файлов; сингулярно: волна имеет счётчик и пропуски с причинами — не «разослали и забыли».

**Приёмка:** `.github/dependabot.yml` 200 ×16; первый цикл без Invalid workflow file; лог created/skipped сохранён в доктрине.

## T21 · Мембранная волна — предложение «Мембрана как код: membrane-check и template-sync»

**Мир:** CODEOWNERS + rulesets — современная мембрана: code owners автоматически запрашиваются на ревью, rulesets умеют required-PR и ограничение путей (docs.github.com). SECURITY.md — чек Scorecard Security-Policy (критерии: контакт + слова vuln/disclos). LICENSE: отсутствие лицензии «препятствует security review» (Scorecard License); развилка Apache-2.0 (патентная оговорка) vs MIT (короткий, без патентов) — choosealicense.com. AGENTS.md стал стандартом инструкций AI-агентов (agents.md; стюард — Agentic AI Foundation под Linux Foundation; 60k+ проектов; поддержка в Codex/Jules/Cursor/Copilot/Devin; вложенные AGENTS.md — «ближайший к файлу выигрывает»).

**Своё:** ① **membrane-check** — один workflow в «учителе» runtime-protocol: по живому API обходит 41 репу и проверяет матрицу (CODEOWNERS непуст; SECURITY.md с контактом и vuln-словами; AGENTS.md не пуст; LICENSE у polimat-hub); таблица в step summary; красный при любой регрессии — флагман polymath-os больше не может откатиться молча. ② **membrane-template-sync**: шаблоны версионируются маркером `<!-- membrane-template: vX.Y -->`; weekly-cron открывает PR в репы с отставшим маркером — учитель 9/9 становится единственным источником правды мембран. ③ membrane coverage 100% для polymath-os: скрипт разворачивает паттерны CODEOWNERS на git ls-files и фейлит при непокрытом файле + ruleset required-PR. ④ LICENSE polimat-hub — рекомендация Apache-2.0 (патентная оговорка для репы-хаба с контрибьюторами), решение за Хозяином. Универсально: мембрана = матрица + шаблоны + coverage; сингулярно: гигиена-оценка ПУЛЬСа становится следствием membrane-check, а не ручной таблицей.

**Приёмка:** `license.spdx_id` polimat-hub установлен; membrane-check зелёный на каноне и красный на тестовой регрессии; coverage-скрипт polymath-os выдаёт 0 непокрытых.

## T22 · agryp metabolism CI — предложение «Метаболизм: CI с нулём доверия»

**Мир:** гигиена GitHub Actions как канон: top-level permissions read-only + write только на уровне job (Scorecard Token-Permissions); pin `uses:` на полный SHA (Scorecard Pinned-Dependencies; тег засчитывается лишь при immutable releases — docs.github.com); fail-closed шаги без `|| true` («Secure use of Actions», docs.github.com); Dependabot ecosystem github-actions — официальный (docs.github.com); внешний самопросмотр — ossf/scorecard-action (официальный, free для public). Dependabot × SHA-пины — открытый пункт, не подтверждён документально — названо вслух.

**Своё:** одним коммитом три файла: ① ci.yml «metabolism»: permissions contents:read; checkout по full-SHA; `set -euo pipefail`; gcc -Wall -Wextra -Werror + make demo + make audit — клетка с нулём зависимостей получает CI с нулём доверия (read-only токен, пинненный checkout, fail-closed). ② ПУЛЬС v2 (self-audit.yml): cron + dispatch; самопроверки (все пины 40-hex; permissions read-only; мембраны на месте; freshness SHA с авто-PR refresh) — закрывает Dependabot×SHA собственным обходчиком; рядом scorecard-action как внешний контроль. ③ dependabot.yml github-actions weekly. Эмерджентная связка: metabolism (внешний пульс) + виток 10 (внутренний счёт: метрики/журнал/сигнатуры) — ядро впервые получает согласованную пару счётчиков, сверяемую приёмками. Универсально: шаблон «метаболизм» тиражируется на все C- и файл-как-API репы роя; сингулярно: agryp следит за своим CI так же, как сам следит за юнитами.

**Приёмка:** jq permissions == contents:read; rg не-SHA пинов пусто; workflows list содержит ci.yml + self-audit.yml; первый зелёный прогон; ПУЛЬС 100/100.

## T23 · Минимальный CI ×4 — предложение «First green: веха, а не прогон»

**Мир:** минимальный Python CI — setup-python + матрица + pytest (docs.github.com «Build and test Python»); замена flake8 на Ruff — тренд 2025–2026 (astral.sh/ruff: «10–100× быстрее», один инструмент вместо десятков). Статика: html-validate — offline HTML5 validator (html-validate.org); lychee — async link-checker (lychee.cli.rs); деплой Pages — штатные configure-pages/upload-pages-artifact/deploy-pages (docs.github.com). Scorecard CI-Tests засчитывает зелёные прогоны последних ~30 коммитов — «first green run» = момент, когда репа начинает считаться.

**Своё:** ① polymath-gen: Ruff + pytest на одной версии Python; **ruff-budget** — файл ci/ruff-budget.json с зафиксированным текущим числом нарушений: зелёный = «не хуже бюджета», красный = рост; уменьшение уменьшает бюджет — монотонный ratchet: долг разрешён, но не вечен и не молчалив. ② edinyy-svod + language-through-the-ages: vault-integrity CI — html-validate + lychee + `sha256sum -c SHA256SUMS` + `git diff --exit-code SHA256SUMS` после регенерации (манифест свежести как в T17 — один канон на статику и релизы). ③ **first-green-веха** — эмерджентный ход: при первом успешном прогоне workflow создаёт и закрывает issue «CI: first green run» с датой и хешем коммита — веха истории роя машинно-видима, готова к мембранной таблице T21; СВОД-раунд 5 берёт вехи живым API. Универсально: веха применима ко всем будущим репам («репа родилась» = первый зелёный); сингулярно: даже статика без кода получает метаболизм целостности, а не «что-то гоняется».

**Приёмка:** run list conclusion success по каждой репе; ruff-budget-сравнение в CI; sha256sum -c rc=0; issue «CI: first green run» closed с датой и SHA.

## Эмерджентный синтез: «Пломба-контур II · Метаболизм»

Из одиннадцати предложений складывается второй контур того же организма. «Пломба-контур» I (T01–T12) дал правде **происхождение**: каждая строка генерится из живого API или несёт хеш источника. «Пломба-контур» II (T13–T23) даёт правде **обмен веществ**:

- **рефлекс** — re-run по закону (T13): падение от квоты реанимируется guard'ом, чужая боль открывает вопрос, а не лечится молча;
- **питание** — факт без тела и квота-дозиметр (T14): тяжёлое тело — только в релизном обряде, лёгкие доказательства — всегда;
- **скелет** — живые пины с TTL (T15), манифесты-генераты с проверкой свежести (T17), геном с reconcile-петлёй (T18);
- **кожа** — мембраны как код: матрица, шаблоны, coverage (T21);
- **иммунитет** — алерты включены и замкнуты конфигом, возраст алерта — метрика (T19, T20);
- **пульс** — ПУЛЬС v2 agryp с самопросмотром пинов и permissions (T22), вехи first green (T23); исключение из линта — только с маркером и стражем (T16).

Ни один орган не нов для мира поодиночке (Argo, Renovate, Scorecard, journald-sealing, textfile collector — всё названо с источниками). Ново то, что они собраны **одним организмом на файлах и хешах, без сокетов, серверов и ручных чисел**, и что у каждого дрейфа есть три законных исхода: догониться автоматически, стать громким, закрыться машиной. Четвёртый исход — тихий дрейф — запрещён как класс. Это мировой стандарт качества, исполненный средствами одного аккаунта, — целиком копируемый любым аккаунтом любого размера.
