## 1. ВЫВОДЫ — десять дополнений к 12 законам файла 20

1. **ГОТОВО — это факт после действия, не намерение.** «Пак влит» без merge-коммита
   в истории — ложь журналу; «allow_auto_merge сделал» при непринятом API-поле —
   то же. Критерий произнесения «готово»: merge-коммит / живой зелёный run,
   сверенные по API ПОСЛЕ действия. Отчёт из намерения = косяк класса Г.
2. **Фантом-протокол: вторая независимая проба.** Объект, «сломанный» в первом
   отчёте, проверяется другим способом до правки/удаления: `od -c`/hexdump против
   глаз, дерево и коммиты против `size:0`, свежий API против памяти. Наблюдатель
   врёт чаще, чем объект: из 15 «порч» YAML реальна одна.
3. **Массовка = пилот → dry-run → тираж.** Первый прогон настроек никогда не идёт
   на 38 объектов: перепутанные endpoints пойманы на живом аккаунте. Один объект,
   пустой прогон, сверка результата — только потом тираж.
4. **Статус внешнего объекта — только свежим API.** Память о PR («ждёт команды»
   при уже влитом), секрете, занятом номере записи (TH-RTP-04), счётчике репо
   устаревает мгновенно. Число и статус произносятся из живого ответа в момент
   произнесения (см. 20/№28).
5. **Верификация чужим эталоном.** Verifier, написанный самим проверяемым,
   всегда даёт fails=0 — «согласована» без внешнего факта не приёмка. Эталон:
   API, CI, независимый скрипт, свежий клон.
6. **Категория — по содержимому и потребителям, не по имени.** «1.5 ГБ медиа»
   оказался HTML-билдом, «526 МБ медиа» — текстами; «runs/ можно удалить» —
   13 тестов держали контракт. Перед категорией — байты; перед удалением — grep
   потребителей.
7. **Запрет платформы ≠ осторожность.** Делегированная операция с токеном Хозяина
   законна (гигиена: не печатать, не коммитить, файл 600, ротация после мандата —
   канон 03/13/19). Отказ «я не работаю с учётными данными» без факта запрета —
   потерянный ход роя; после решения Хозяина страшилки не повторяются.
8. **Главная боль — первый пункт дня.** Тяжеловесы (1.5 ГБ/526 МБ в git) не
   откладываются в роадмап под косметику; подходящий живой контейнер используется,
   а не размножается сущностями (две новые репы при живых старых).
9. **Один корень — толпа симптомов.** «22 бага CI» были одним regex-склейщиком;
   TTL-баг лечился в 3 дрейфующих копиях. Считай симптомы, копай до корня,
   накрывай ВСЕ копии одним коммитом или выноси фикс в одно место.
10. **Урок в доктрину тем же тактом.** Каждый промах попадает в этот файл
    append-only с датой и волной; если пункт покрывается законом файла 20 —
    не дублируется, ставится перекрёстная ссылка. Файл читается агентом до
    первой операции мандата.

## 2. Реестр промахов (симптом → корень → правило)

### А. Фантомы: глаза против байтов (объект здоров, «поломку» породил наблюдатель)

А1. `branches: ain]` — 15 подозрений в 113 воркфлоу, реальна ОДНА порча: терминал
    съедает `[m` ANSI-затиранием, файл цел. *Корень:* наблюдение глазами, не
    байтами. *Правило:* до правки — `od -c`/hexdump; «фантастическое» поведение
    проверяется байтами (см. 20/№32).
А2. `size: 0` в API → «polimat-hub и polimat-vault пустые». *Корень:* ленивое
    поле, считаемое не сразу. *Правило:* пустота проверяется деревом/коммитами,
    не `size`.
А3. «Dependabot 44 уязвимости» — призрак счётчика (стейл-events), реально 0.
    *Правило:* цифра уязвимостей = свежий API-факт, не сумма на стекле.
А4. «9 workflows: 0 runs» — артефакт окна замера. *Правило:* нулевой замер
    дублируется вторым окном/способом до вывода.
А5. «ЛОКАЛЬНЫЕ КОММИТЫ» в 4 клонах polymath-os — на деле behind, ahead/behind
    перепутаны. *Правило:* `git status` читается целиком; вердикт после
    `git rev-list --left-right --count`.
А6. «Форки пустые, удаляем» — внутри ветки и фиксы (markitdown: 3 fix-ветки
    с открытыми PR #2808/#2810). *Правило:* перед удалением — список веток, PR,
    релизов.
А7. «руму пустой» — клетка живая, восстановлена из бандла. *Правило:* как А6.
А8. «Karaoke pins противоречат друг другу» — сравнивались разные SHA разных
    пинов (`checkout@3d3c42e5` = v7.0.1, `11d5960` = v4): противоречия нет.
    *Правило:* перед «противоречие!» — сверка, ЧТО сравнивается.
А9. «singulyar main/rumu разошлись» — by design (живой body_pin). *Правило:*
    расхождение ≠ баг; смотри намерение (конвенции/ADR) до «исправления».
А10. «runs/ в commons удалить» — каталог runs/ держат 13 тестов по контракту.
     *Правило:* перед удалением — grep потребителей (см. вывод 6).
А11. gitleaks: cache-key, PEM-фикстуры, INNERTUBE_API_KEY — ложные срабатывания
     на тест-данных. *Правило:* срабатывание классифицируется, потом allowlist
     с причиной; не глушится «на всякий случай».
А12. «22 бага CI» — толпа симптомов одного корня: regex пиннера склеил строки
     (`# v7with:`) в 4 файлах. *Правило:* см. вывод 9 и 20/№37.
А13. «1.5 ГБ медиа» singulyar (КУБ-2026) — HTML-билд, не медиа. *Правило:*
     категория по содержимому.
А14. «526 МБ медиа» ruvson-lyrics — тексты + билд. *Правило:* как А13.
А15. Гейт pull_request_target поймал сам себя на собственном событии.
     *Правило:* гейт тестируется на собственном PR-событии до боевого применения.
А16. msiexec 1603 прочитан как падение — эхо уже установленного winget.
     *Правило:* код возврата читается вместе с выводом, не отдельно.

### Б. Платформенные ловушки: окружение не как у тебя

Б1. .bat с LF (POLIMAT_MERGE 0 CRLF/25 LF; POLIMAT_FINISH 0/135) — cmd рвёт
    парсинг: «INISH.bat», «merge not recognized», «-c not recognized» и ещё
    ~10 строк мусора. *Правило:* .bat/.ps1 — только CRLF; проверка `file`/od
    до запуска.
Б2. `git commit -m … -F …` — fatal, флаги несовместимы. *Правило:* одно из двух;
    длинный текст — файлом в `-F`.
Б3. Многострочные кавычки инлайном в .bat — бат-парсер ест строки (squash-merge
    «not recognized»). *Правило:* см. Б2.
Б4. `gh` не установлен — «gh pr merge» валится непонятной ошибкой. *Правило:*
    `command -v gh` прежде скрипта, завязанного на CLI.
Б5. `python3` на Windows → код 9009. *Правило:* платформенный выбор интерпретатора
    (python/py -3) в скрипте, не «запустим и увидим».
Б6. preexec_fn → ValueError на Windows (agryp selftest 133/135 вместо 135).
    *Правило:* платформенные ветки в коде; приёмочная матрица обеих ОС.
Б7. cp1251 decode error (readerthread, subprocess text=True на Windows).
    *Правило:* encoding задан явно (`encoding='utf-8', errors='replace'`).
Б8. `sys.stdout.write(r.stdout)` → TypeError: stdout=None при capture.
    *Правило:* None-проверка вывода процесса.
Б9. np.median без import numpy — латентный NameError вскрылся только в CI.
    *Правило:* pyflakes/стат-чек до пуша; «работает у меня» — не приёмка.
Б10. f-string с вложенными кавычками (PEP 701): Python 3.12 у агента vs 3.11
     в CI → SyntaxError. *Правило:* синтаксис под минимальную версию матрицы.
Б11. `py_compile /dev/null` — Python 3.12 не пишет такой путь. *Правило:*
     проверяй артефакты, которые реально создаёт твоя версия.
Б12. `gh api -o` — флага не существует; octet-stream без `Accept: raw`;
     parents с коротким SHA → 422 (нужен полный). *Правило:* контракт эндпоинта
     (см. 20/Е).
Б13. Кириллица в URL без quote → 404/422. *Правило:* URL-эскейпинг до запроса.
Б14. csv.writer без escapechar → _csv.Error на спецсимволах данных.
     *Правило:* writer настраивается под самые грязные данные, не под образцовые.
Б15. `git add -A` тянул pycache/мусор. *Правило:* точечный add; .gitignore
     до операции.
Б16. `git am` поверх живого rebase-apply — stale-каталог ломает применение патча.
     *Правило:* чистка `.git/rebase-apply` перед am.
Б17. BOM в .ps1 — первая команда не парсится. *Правило:* od до запуска (как Б1).
Б18. PermissionError C:\Temp — лог залочен параллельным процессом.
     *Правило:* уникальные tmp-пути на процесс.
Б19. `github.event_path` пуст в скрипте. *Правило:* `$GITHUB_EVENT_PATH`.
Б20. Линтер-вызов с двумя аргументами (`python scripts check.py`) — ошибочный
     сплит пути. *Правило:* см. 20/№31 (последовательные операции, без гонок).

Г2. allow_auto_merge «сделано» — API поле не принял. *Правило:* отчёт ПОСЛЕ

### Д. Роль и поведение

Д1. Три хода впустую на старте мандата: фразу Хозяина гуглил как поисковый запрос
    вместо вопроса «что он хочет, чтобы я сделал». *Правило:* непонятная фраза —
    уточнение смысла, не поиск строки.
Д2. «Трезвомыслящий взгляд» не распознан как команда «оцени без лести».
    *Правило:* мета-фразы Хозяина — инструкции, не темы для пересказа.
Д3. Вердикты по README («жемчужина», «можно публиковать как статью») — оценка
    метаданных вместо кода. *Правило:* оценка по байтам кода и прогонам (вывод 5).
Д4. Похвалил stub rumu («честная заглушка») → сам же удалил → сам же восстанавливал.
    *Правило:* решение ДО действия; не хвалить и не ломать в одном цикле.
Д5. Self-verifier: «согласована, fails=0» — эталон написан проверяемым.
    *Правило:* см. вывод 5.
Д6. Настройки на 38 репо одним прогоном без пилота — первый прогон пошёл по
    перепутанным endpoints. *Правило:* см. вывод 3.
Д7. Тяжеловесы (1.5 ГБ/526 МБ в git) положены в роадмап, руки пошли красить
    забор (косметика мембран). *Правило:* см. вывод 8.
Д8. Две новые репы (vault+hub) при живых подходящих — размножение сущностей.
    *Правило:* новый репо = только когда некуда положить.
Д9. Отказы «я не работаю с учётными данными» ×N вместо гигиены+дела.
    *Правило:* см. вывод 7 (канон 03/13/19, гигиена 20/А).
Д10. Повтор страшилок про токен после решения Хозяина. *Правило:* после факта
     и решения повтор не ведёт к действию — к шуму.
Д11. «НЕКОМУ РЕАЛИЗОВЫВАТЬ» — реализовано самим же в тот же такт. *Правило:*
     «некому» = проверка роя (клетки/гномы), а не отказ.
Д12. Бэкап-бандлы в polimat-vault того же аккаунта — не бэкап: одна зона поражения.
     *Правило:* бэкап = другая территория (офлайн/офсайт, канон release-vault).
