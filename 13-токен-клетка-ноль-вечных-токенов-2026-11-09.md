## Правила клетки (5)

1. **Инвентарь.** Каждый секрет всех репо аккаунта имеет запись в
   `secrets-inventory.jsonl` (append-only): `{snapshot_at, repo, secret, updated_at, note}`.
   Наполнитель — read-only команда `python3 scripts/token_cage.py pull`
   (Actions secrets API через `gh`; выполняет агент-держатель, см. правило 3).
   Строка для Свода: `python3 scripts/token_cage.py svod-line`.
2. **TTL.** Секрет старше 30 дней = долг (громкость как у депт-аудита).
   Гейт: `python3 scripts/token_cage.py ttl` — печатает долги и падает с exit 1,
   если хоть один секрет перешёл границу.
3. **Мутация.** Обновление секрета — единственная мутация клетки; делает её только
   агент-держатель `.token_active` (протокол верификации §10.3-9), через web-UI;
   после обновления — новая append-only запись в инвентаре (старые не переписываются).
4. **Пуш-щит.** На всех публичных репо включены push protection и secret scanning
   (бесплатно на публичных). Дублирующий гейт в репо: `python3 scripts/token_cage.py scan`
   — ноль PAT-подобных строк во всех файлах, кроме инвентарных артефактов клетки.
5. **Цель-горизонт.** Остаётся ровно один мастер-PAT (токен агента); всё остальное —
   `GITHUB_TOKEN` или OIDC-федерация Actions (короткоживущие, без хранения).

## Как критерии приёмки закрываются скриптом

| Критерий | Команда | Что даёт первый прогон |
|---|---|---|
| 1. Инвентарь в Своде живой (≤ 24 ч) | `pull` + `svod-line` | jsonl-инвентарь + готовая строка для `12-свод-недоделок-2026-11-08.md` |
| 2. Ноль секретов старше 30 дней | `ttl` | список долгов; exit 1 при нарушении |
| 3. Ноль PAT-подобных строк в артефактах | `scan` | файл:строка каждого попадания; exit 1 при нарушении |

## Сниппет воркфлоу (скопировать в `.github/workflows/wave3-token-cage.yml`)

```yaml
name: wave3-token-cage
on:
  workflow_dispatch:
  push:
    paths: ["scripts/token_cage.py", "secrets-inventory.jsonl"]
jobs:
  cage:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v4
      - name: Клетка · скан PAT-строк
        run: python3 scripts/token_cage.py scan
      - name: Клетка · TTL 30 дней
        run: python3 scripts/token_cage.py ttl --inventory secrets-inventory.jsonl
```

`pull` в CI не выполняется: списки Actions-секретов читаются только админ-токеном,
инвентарь наполняется локально агентом-держателем (read-only по отношению к репо).

## Ход для роя

Инвентаризация — read-only и копируется в любой репо роя одной командой; обновление
секрета — единственная мутация, и её делает только держатель `.token_active`; чужие
журналы и инвентари рой только читает, свои — только дополняет (правило генома).
