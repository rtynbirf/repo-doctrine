# agentic · пилот «Markdown → Actions» (Э-2.4, repo-doctrine#18)

**Идея:** задачи для роя описываются на естественном языке в Markdown-файлах,
машинная часть каждой задачи — блоки ```sh. Компилятор `tools/md2actions.py`
превращает папку `agentic/` в исполняемые проверки внутри GitHub Actions.

**Контекст мира:** GitHub Agentic Workflows (github/gh-aw) стали **GA 28.10.2026** —
это промышленная версия того же паттерна (Markdown → компиляция → Actions),
но для её движка нужна лицензия Copilot. Настоящий пилот — **stdlib-компилятор
без лицензий**: работает на любом runner'е, fail-closed, и живёт рядом с доктриной.
Когда у Хозяина появится Copilot-лицензия, файлы формата не пропадут: тот же
принцип «задача = Markdown» переносится на gh-aw один-в-один.

## Формат задачи

~~~markdown
# ЗАДАЧА-NN · Короткое имя

(естественный язык: зачем, что считается успехом)

```sh
проверка 1
проверка 2
```
~~~

- Каждый файл `agentic/ЗАДАЧА-*.md` — независимая задача.
- Все блоки ```sh исполняются по порядку, `set -euo pipefail`;
  первый не-ноль = красный прогон (fail-closed, никаких `|| true`).
- Итоги — в job summary волны.

## Запуск

```bash
python3 tools/md2actions.py agentic/          # компиляция + исполнение
python3 tools/md2actions.py agentic/ --list   # только перечень задач
python3 tools/md2actions.py agentic/ --dry    # компиляция без исполнения
```

CI: `.github/workflows/agentic-pilot.yml` — еженедельно по понедельникам + ручной диспатч.

## Честные границы

- Секреты не выводятся в логи; кросс-репо чтение — под `GITHUB_TOKEN`
  (публичные клетки) или под владельческим патом вне CI.
- Задачи не коммитят в репо: только проверки и отчёт. Пишущие агентные
  воркфлоу — отдельное решение после пилота.
