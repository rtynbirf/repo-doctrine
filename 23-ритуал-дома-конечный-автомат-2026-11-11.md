## 1. Автомат (теория → практика)

Каждая работа агента — конечный автомат (finite state machine). Ни одно состояние не может висеть бесконечно: у автомата есть финал, и агент обязан привести работу до финала сам, без внешнего принуждения.

```
S = { ВЗЯЛ, СДЕЛАЛ, УБРАЛ, ДОМ_ЧИСТ, ПЕРЕДАЛ }

δ (таблица переходов):
  ВЗЯЛ   → СДЕЛАЛ     : работа исполнена живым фактом (закон §5: факт = байты)
  СДЕЛАЛ → УБРАЛ      : последствия убраны (см. §3 — уборка обязательна)
  УБРАЛ  → ДОМ_ЧИСТ   : приёмка сверена, отчёт издан, счётчик пересчитан
  ВЗЯЛ   → ПЕРЕДАЛ    : честная передача с фактами и приёмкой (НЕ молчаливое висение)
  ПЕРЕДАЛ → ВЗЯЛ      : следующая волна/агент приняла работу

ЗАПРЕЩЁННЫЕ СОСТОЯНИЯ (не существуют в легальном автомате):
  «висит открытой, потому что некому», «сделано, но не закрыто»,
  «ответил в чате вместо репо», «оставил notification Хозяину, который
  мог закрыть сам».
```

## 2. Закон дома (инвариант)

1. **ЧЕЛОВЕК НЕ ЗАНИМАЕТСЯ ТЕМ, ЧТО МОЖЕТ ДЕЛАТЬ АГЕНТ БЕЗ НЕГО.** Всё, что исполняется машиной/агентом, исполняется машиной/агентом: закрытие issues, разметка notifications done, пересчёт счётчиков, уборка временных артефактов.
2. **НИКАКИХ НОТИФИКАЦИЙ И OPEN-ХВОСТОВ ОТ СДЕЛАННЫХ РАБОТ.** Notification = неоконченный переход. Увидел → разобрал → mark done. Не «сбросил», а разобрал: ответ, закрытие или честная передача.
3. **ВСЁ ЗАКРЫВАЕТСЯ И РЕШАЕТСЯ САМОСТОЯТЕЛЬНО** — на уровне агента и волн, в рамках законов роя (закон §5: закрытие только живым фактом; решение Хозяина остаётся решением Хозяина — этот класс работ агент передаёт ему ОДНИМ пунктом, без дежурных пингов).
4. **АВТОМАТИЧЕСКОЕ ИСПОЛНЕНИЕ — ДЕФОЛТ.** Если работу можно настроить на крон/Action/скрипт — она настраивается на крон/Action/скрипт, а не повторяется руками.

## 3. Уборка (УБРАЛ) — чек-лист перехода

| След работы | Уборка |
|---|---|
| Notification от события, которое уже разобрано | `PUT /notifications/threads/{id}` → done (официальный API; inbox zero роя = 0) |
| Issue, чья приёмка исполнена | факт-комментарий + `PATCH state=closed, state_reason=completed` (закон §5) |
| Временные файлы сессии (`/tmp`, локальные черновики) | удаляются/архивируются в REPORT/audit; ничего живёт только в памяти сессии |
| Токен, побывавший в чате | пометка в отчёте «отзыв за Хозяином» (П-35) — единственный честный хвост |
| Конфликты параллельных волн | сводятся аддитивно (дубли удаляются, факты объединяются) — грабля Я-22/дубли секций |
| Чужая скорость (remote ушёл вперёд) | stash → rebase → pop → add конкретных файлов → push → SHA-верификация |

## 4. Исполнительный гейг — машина дома

`polimat-hub/tools/house_automaton.py` — детектор висящих переходов по всему дому:
- **Сенсор 1 · Notifications:** `GET /notifications` — каждое живое notification = висящий переход; режим `--clean` — разметка done (действие, не отчёт).
- **Сенсор 2 · Красные CI:** последний прогон на default-ветке каждого репо; красный за 72 часа = долг (старше — история, пломбы волн).
- **Сенсор 3 · Открытые карты:** открытые issues ×51 (живые карты роя — не мусор, но считаются и стареют).
- **Вердикт:** `ДОМ ЧИСТ` (0 notifications · 0 свежих красных) либо список долгов с состоянием автомата по каждому.
- Выход: JSON в audit/ + ПУЛЬС-строка. Токен только env. Только stdlib.

## 5. Сверка с миром (2026-11-11)

- Агенты 2026 — «долгоживущие владельцы workflow», self-correcting контуры (Towards AI, август 2026): stateless-обёртки умерли — наш автомат запрещает stateless-переходы конструктивно.
- ALM-цикл агентов 2026 (planning→building→testing→deploying→monitoring→governing→retiring, jadasquad) — наш УБРАЛ закрывает retiring/governing ноги, которых в мире чаще всего нет.
- Inbox Zero как автоматизируемая практика (getinboxzero; GitHub Notifications REST API: «Marks a thread as done» — официальный endpoint) — рой делает inbox zero API-машиной, а не руками.
- Отличие от мира (уникальное): у мира автомат закрывается «уведомлением человеку»; ЗАКОН ДОМА закрывает его ДО человека — человек получает ДОМ ЧИСТ и решения, а не очередь уведомлений.
