## 0. Универсальный принцип

**Вечный ключ = вечная рана.** Ноль вечных ключей: каждый ключ имеет дату смерти,
известную ДО рождения, и живёт в наименьшем из возможных конвертов.

## 1. Конверт в три канала

| Канал | Что | Ключ | Срок жизни | Кто делает |
|---|---|---|---|---|
| 1. Воркфлоу роя | обычные CI/диспетчи внутри репо | встроенный `GITHUB_TOKEN` (+ `OIDC` для внешних облаков) | одна джоба | рой |
| 2. Единственный человеческий ключ | меж-репо операции роя (пин-дозор, пульс, бандлы) | `fine-grained PAT`, скоуп только тронутых операций | ≤90 дней, календарная ротация + напоминание за 7 дней | Хозяин (web-UI) + рой (обновляет секреты) |
| 3. Длинные интеграции | постоянные межагентные мосты | **GitHub App** (first-party идентичность, аудит-трейл) | ключи App ротируются сами (installation token = 1 час) | Хозяин (web-UI) |

Свойство конверта: просрочка ключа = тишина (worst case — красный гейт), а не утечка.

## 2. Машинная приёмка каналов

1. **Канал 1**: `grep -r "ghp_" .github/workflows/` → 0 попаданий; секреты только через `secrets.*`.
2. **Канал 2**: `GET /users/rtynbirf/packages` без токена → 401; длина жизни PAT видна в ответе
   `x-github-token-expiration` (fine-grained); в `github-runbook` крон-напоминание за 7 дней до смерти.
3. **Канал 3**: список установленных App через API; каждое межагентное действие оставляет запись в
   audit log — приёмка «действие найдено по актору App, а не по PAT».

## 3. Сниппет OIDC для воркфлоу роя (канал 1 → внешние цели)

```yaml
permissions:
  contents: read
  id-token: write   # OIDC-токен живёт одну джобу и истекает сам
jobs:
  ship:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@8f4b7dd84864484a7bf31766abe9204da3cbe65b # v3.5.0 (SHA-канон)
      - name: Облачь цели через OIDC (пример: AWS)
        run: echo "внешняя цель получает короткоживущий токен, ключ не хранится"
```

## 4. Чек-лист выпуска fine-grained PAT (канал 2, руки Хозяина, ≤5 минут)

0. Выпущенный ключ проверяется живой пробой ДО первого использования (закон №11,
   `03-токены-и-секреты.md`): `GET /user` → HTTP 200; дата смерти из заголовка
   `github-authentication-token-expiration` — в календарь ротации (п. 6).
1. Settings → Developer settings → Fine-grained tokens → Generate new token.
2. Resource owner: `rtynbirf`. Repository access: **только тронутые волной репо** (не «all repositories»).
3. Permissions: Contents: Read+Write; Actions: Read+Write; Administration: Read (только если волне
   нужны настройки репо). Всё остальное — No access.
4. Expiration: ≤90 дней (для сессии роя — 7–30 дней).
5. Выдан в чат роя → рой считает его **скомпрометированным с момента вставки в чат** (доктрина 03):
   работает в окне мандата, после — обязательная ротация, секрет `GH_PAT` хаба обновляется
   `update_ghpat.py` (sealed box, HTTP 204).
6. Ротация в календарь github-runbook: напоминание за 7 дней до смерти ключа.
