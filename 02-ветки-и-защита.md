# 02 · ВЕТКИ И ЗАЩИТА MAIN

## Философия (коротко)

Мы работаем в **агентском режиме**: прямые пуши в `main` разрешены — иначе
автоматика буксует. Но разрешить пуши — не значит разрешить **порчу истории**.
Поэтому защита настроена так:

- ❌ force-push в main — ЗАПРЕЩЁН (историю нельзя переписывать)
- ❌ удаление main — ЗАПРЕЩЕНО
- ✅ обычные пуши/merge — РАЗРЕШЕНЫ без ревью и очередей

История репозитория — это ворклог, отлитый в камень: события не переигрывают,
их исправляют **новыми** событиями (`git revert`).

## Что включено на 2026-11-01

| Тип репо | Защита ветки | Почему |
|---|---|---|
| Публичные (все 11) | **ВКЛ** API на default-ветку | Бесплатный план позволяет |
| Приватные (6) | НЕ включена | GitHub отдаёт это только на Pro/Team: «Upgrade to GitHub Pro…». Как будет Pro — включить по чек-листу ниже |
| Архивы (rumu, H-PE11) | не трогали | read-only, защита не нужна |

Включённая защита (для публичных) выглядит так:

```
required_status_checks:        null   (не требуем CI — CI пока нет)
enforce_admins:                false  (Хозяин может всё)
required_pull_request_reviews: null   (прямые пуши разрешены)
restrictions:                  null   (пушат все, у кого есть права)
allow_force_pushes:            false  ← суть защиты
allow_deletions:               false  ← суть защиты
lock_branch:                   false
required_linear_history:       false
```

## Как включить на приватных репо (когда появится GitHub Pro)

UI: репо → `Settings` → `Branches` → `Add branch protection rule` →
Branch name pattern: `main` → отметить:
- ☐ Require a pull request before merging — **НЕ отмечать** (нам нужен прямой пуш)
- ☑ Do not allow force pushes
- ☑ Do not allow deletions

API:

```bash
curl -XPUT -H "Authorization: Bearer $GH_TOKEN" \
  https://api.github.com/repos/OWNER/REPO/branches/main/protection -d '{
  "required_status_checks": null, "enforce_admins": false,
  "required_pull_request_reviews": null, "restrictions": null,
  "allow_force_pushes": false, "allow_deletions": false,
  "required_linear_history": false, "lock_branch": false}'
```

## Правила работы с main

1. **main всегда рабочий.** Коммит, после которого репо не запускается, —
   авария. Не уверен, что код живой, — веди ветку, сливай PR-ом.
2. **Откат — только `git revert`.** Force-push в main запрещён технически
   (публичные) и морально (всегда):
   ```bash
   git revert <sha>          # один плохой коммит
   git revert -m 1 <merge>   # плохой merge
   git push origin main
   ```
3. **Конфликт с другим агентом.** Если `git push` отклонён («not fast-forward») —
   у коллеги ушла вперёд история. Правильно: `git fetch` → `git rebase origin/main`
   (или `merge`) → разрулить → пуш. Неправильно: `push --force`. Никогда. Ни при каких обстоятельствах.
4. **Переименование default-ветки** — только по мандату Хозяина: слетают
   protection-правила, ссылки Pages, клоны агентов.
5. Ветки живут недолго: merged → удалилась сама (флаг включён). Ветка старше
   месяца без активности — кандидат в мусор, но удалять чужие ветки вежливо
   только спросив.

## Временное снятие защиты

Только Хозяин или агент с явным письменным мандатом:
`Settings → Branches → Rule set → Edit → Disable`, сделать дело → включить обратно.
В ворклог записать: кто, зачем, когда снял и вернул.
