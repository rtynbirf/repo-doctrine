# 07 · 2FA ЗА 7 ШАГОВ (единственная дверь, открытая только Хозяину)

**Почему это не сделал агент (и не сделает ни один):** у GitHub API нет
команды включения 2FA — принципиально. Если бы токен мог управлять вторым
фактором, кража токена означала бы полный захват аккаунта с отключением
защиты. GitHub сознательно оставляет это владельцу пароля. Это замысел:
второй фактор и должен быть вторым фактором.

**ТЕЛЕФОН НЕ НУЖЕН. И СТОРОННИЙ СОФТ ТОЖЕ НЕ НУЖЕН.** Требование GitHub —
второй фактор, а не телефон и не чужая программа. TOTP-ключ — это текстовая
строка; шесть цифр из неё считаются встроенным в Windows .NET. История
правок: первая редакция упиралась в мобильные приложения, вторая — в
KeePassXC; Хозяин отверг обе зависимости. Итог — путь 0: свой генератор,
ноль сторонних, ноль установок.

## Разбор возражения «завтра сторонние куякнутся» (чтобы спорить фактами)

- KeePassXC и подобные — НЕ СЕРВИС. Нет сервера, нет аккаунта, нет
  продления подписки. База (.kdbx) — локальный файл на диске;
  мастер-пароль — ключ шифрования ТВОЕГО файла, его никто не видит.
  Даже если проект умрёт — формат открытый, файл откроют десятки
  совместимых программ.
- Но требование принято: зависимости исключены полностью. Путь 0
  использует только то, что уже встроено в Windows.

## Путь 0 (основной): totp.ps1 — ноль сторонних программ

Свой генератор лежит в `cell65-host` → `tools/totp.ps1`: чистый
PowerShell 5.1 (работает и на 7), никуда не ходит по сети, установок не
требует. Проверено: векторы RFC 6238 — 5/5 зелёные, живой синхрон с
эталонной реализацией — зелёный (TH-GH-04).

1. **Скачать один файл:**
   `https://raw.githubusercontent.com/rtynbirf/cell65-host/main/tools/totp.ps1`
   (в любую папку, например `C:\2fa\`).
2. **GitHub:** `Settings` → `Password and authentication` →
   `Enable two-factor authentication` → пароль аккаунта → выбрать
   `Authenticator app` → на экране с QR нажать ссылку
   **`enter this text code instead`** → скопировать показанный ключ.
3. **Сохранить ключ в сид** (в папке с totp.ps1, вставив СВОЙ ключ):
   ```
   'КЛЮЧ_ИЗ_GITHUB' | Set-Content -Encoding ASCII totp.seed
   ```
4. **Получить код:**
   ```
   powershell -ExecutionPolicy Bypass -File totp.ps1
   ```
   Скрипт напечатает 6 цифр и сколько секунд они живут.
5. **Вставить 6 цифр в GitHub** → `Continue`. Всё — 2FA включена.
6. **КОДЫ ВОССТАНОВЛЕНИЯ — ОБЯЗАТЕЛЬНО.** GitHub покажет 10 одноразовых
   кодов → `Download` → файл на флешку И копией в отдельную папку диска.
   ДВА МЕСТА. НЕ в репо, НЕ в чат. Это единственный вход, если сид/бокс
   умрут.
7. **Проверка.** Приватное окно браузера → вход в GitHub → должен
   спросить 6 цифр (запусти totp.ps1 ещё раз) → щит поднят.

Гигиена: `totp.seed` хранить ТОЛЬКО локально — не коммитить (в `.gitignore`
cell65-host добавлен), не слать в чат. Если сид где-то засветился — сид
перевыпускается: в GitHub можно сгенерировать новый (re-setup TOTP),
старый умирает. Скрипт читает только локальный файл и в сеть не ходит.

## Путь A (если захочется сейф): KeePassXC

Менеджер паролей + генератор TOTP в одной офлайн-базе. Не сервис — см.
разбор выше. Скачал, установил, создал базу, мастер-пароль на бумагу;
запись «GitHub (rtynbirf)» → TOTP → Setup TOTP → вставить тот же ключ.
Коды восстановления — вложением в базу и на флешку.

## Путь B (минимализм с окном): WinAuth

`github.com/winauth/winauth` — маленькое Windows-приложение, только TOTP.
Минус: один файл без мастер-пароля — копию держать на флешке.

## Путь C (если захочется синхронизации): Ente Auth

`ente.io/auth` — открытый код, десктоп-версии, офлайн-режим,

## Бонус после включения: пасскей Windows Hello (тоже ноль сторонних)

`Settings` → `Password and authentication` → `Passkeys` → `Add a passkey`
→ Windows Hello (PIN бокса). Встроен в Windows, как и PowerShell.
Дальше GitHub будет просить PIN бокса, а не 6 цифр. Нюанс: пасскей живёт
в профиле Windows этого бокса. Бокс умер — вход по кодам восстановления,
затем перевыпуск пасскея. Поэтому коды — святое, см. шаг 6.

## После включения

- **Агентский пайплайн не ломается:** git-пуши работают по токенам (PAT),
  2FA на них не влияет. Отвалится только вход в браузер без второго
  фактора — то, ради чего всё.
- Браузерные сессии, где уже вошли, продолжат работать; следующий вход
  попросит второй фактор.
- Ежемесячная проверка (по `03-токены-и-секреты.md`): коды на месте,
  пасскей/ключи узнаваемы, чужих входов в Security log нет.
- Отметить в ворклоге: строка «2FA включена».

## Аудит агента по API (2026-11-01, TH-GH-03)

Всё, что токен берёт, агент проверил сам: 20 репо — deploy keys: 0,
прямые соавторы: только владелец, вебхуки: 0, Actions-секреты: 0.
Аномалий нет. Поле `two_factor_authentication` fine-grained токен не
отдаёт (особенность нового типа токенов) — истина в браузере:
`Settings → Password and authentication`: если 2FA выключена, там висит
жёлтая плашка Enable two-factor authentication с пометкой critical.
SSH/GPG-ключи профиля и Authorized OAuth Apps API не отдаёт — глянуть
руками: там должно быть пусто.
