# 07 · 2FA ЗА 5 ДЕЙСТВИЙ (батник-автомат; дверь открыта только Хозяину)

**Почему это не сделал агент (и не сделает ни один):** у GitHub API нет
команды включения 2FA — принципиально. Если бы токен мог управлять вторым
фактором, кража токена означала бы полный захват аккаунта с отключением
защиты. GitHub сознательно оставляет это владельцу пароля. Поэтому и
батник не может дожать 100%: пароль, тычки Enable и ввод 6 цифр — это и
есть второй фактор. Всё остальное батник делает сам.

**ТЕЛЕФОН НЕ НУЖЕН. СТОРОННИЙ СОФТ НЕ НУЖЕН. РУКАМИ ПОЧТИ ТОЖЕ НИЧЕГО
ДЕЛАТЬ НЕ НУЖНО.** TOTP — это математика (HMAC-SHA1 от счётчика времени),
она считается встроенным в Windows .NET. История правок: первая редакция
упиралась в мобильные приложения, вторая — в KeePassXC, третья — в ручное
скачивание по raw-ссылке (сломалось, когда cell65-host переключили в
приватный: raw анонимам отдаёт 404). Итог — путь 0: батник, который
умеет оба пути скачивания и сам делает всю технику.

## Разбор возражения «завтра сторонние куякнутся»

- KeePassXC и подобные — НЕ СЕРВИС: нет сервера, аккаунта и продлений;
  база — локальный файл, мастер-пароль — ключ шифрования твоего файла,
  формат открытый. Но требование принято: в пути 0 стороннего софта ноль.
- Единственный «сторонний» в схеме — сам GitHub. Его дверь и запираем.

## Путь 0 (основной): 2fa-setup.bat — один файл, автомат

1. **Скачать батник в любую папку** (например `C:\2fa\`):
   `https://raw.githubusercontent.com/rtynbirf/cell65-host/main/tools/2fa-setup.bat`
   Если ссылка отдала 404 — cell65-host сейчас приватный. Тогда открой
   залогиненным страницу
   `https://github.com/rtynbirf/cell65-host/blob/main/tools/2fa-setup.bat`
   → кнопка `Raw` → `Ctrl+S` → сохранить в ту же папку.
2. **Запустить двойным тычком.** Дальше батник сам:
   - достанет `totp.ps1`: сначала по raw-ссылке; если репо приватный —
     сам откроет страницу файла в браузере и будет ждать, пока ты
     сохранишь его кнопкой `Raw` (появился файл — батник продолжил сам);
   - откроет страницу `Enable two-factor authentication` в браузере;
   - покажет список из 5 тычков: пароль → Enable → `Authenticator app`
     → ссылка ПОД картинкой-QR (`enter this text code instead`) →
     скопировать строку-ключ;
   - спросит строку-ключ: вставил → Enter. Сид запишется сам
     (`totp.seed`), права на файл сузятся сами (icacls);
   - напечатает 6 цифр и сколько секунд живут.
3. **Вставить 6 цифр в GitHub** → `Continue`. Готово — 2FA включена.
4. **КОДЫ ВОССТАНОВЛЕНИЯ — ОБЯЗАТЕЛЬНО.** GitHub покажет 10 одноразовых
   кодов → `Download` → одна копия на флешку, вторая в папку батника.
   ДВА МЕСТА. НЕ в репо, НЕ в чат. Это единственный вход, если сид/бокс
   умрут.
5. **Проверка.** Приватное окно браузера → вход → запусти батник ещё раз
   → свежие цифры → щит поднят.

Дальше батник = твоё «приложение-аутентификатор»: каждый вход в GitHub —
запусти `2fa-setup.bat`. Перевыпуск ключа: удалить `totp.seed`, запустить
батник заново. Если сид где-то засветился — перевыпуск обязателен.

### Под капотом: tools/totp.ps1

Чистый PowerShell 5.1 (работает и на 7), ноль зависимостей, по сети не
ходит, сид читает только из локального `totp.seed`. Проверено TH-GH-04:
векторы RFC 6238 (SHA-1) 5/5 — 59→287082, 1111111109→081804,
1234567890→005924, 2000000000→279037, 20000000000→353130; грязный сид
(кавычки/пробелы/строчные) переваривается; живой синхрон с эталоном —
зелёный. `totp.seed` внесён в `.gitignore` cell65-host.

## Если что-то выглядит как ошибка (полевой прогон TH-GH-06)

- **«СИДА ЕЩЁ НЕТ» при запуске totp.ps1 руками** — НОРМА до настройки:
  сида ещё нет, его создаёт батник на шаге ключа. Запускать надо
  БАТНИК, а не totp.ps1. Генератор теперь сам это печатает (код 2).
- **«raw не отдал файл»** — репо в приватном режиме, ветка
  предусмотрена: батник откроет страницу файла, жми `Raw` → `Ctrl+S`
  в папку батника — он продолжит сам. Если totp.ps1 уже скачан в
  другое место — положи рядом с батником и запусти заново.
- **GitHub отверг 6 цифр** — ключ скопирован не полностью или протух
  экран настройки: заново открой Enable 2FA → `Authenticator app` →
  ссылка ПОД QR → скопируй строку ЦЕЛИКОМ → удали старый `totp.seed` →
  батник заново с новым ключом.

## Бонус после включения: пасскей Windows Hello (тоже ноль сторонних)

`Settings` → `Password and authentication` → `Passkeys` → `Add a passkey`
→ Windows Hello (PIN бокса). Дальше GitHub будет просить PIN бокса, а не
6 цифр. Пасскей живёт в профиле Windows этого бокса: бокс умер — вход по
кодам восстановления, затем перевыпуск пасскея. Поэтому коды — святое.

## После включения

- **Агентский пайплайн не ломается:** git-пуши работают по токенам (PAT),
  2FA на них не влияет. Отвалится только вход в браузер без второго
  фактора — то, ради чего всё.
- Ежемесячная проверка (по `03-токены-и-секреты.md`): коды на месте,
  пасскей/ключи узнаваемы, чужих входов в Security log нет.
- Отметить в ворклоге: строка «2FA включена».

## Аудит агента по API (2026-11-01, TH-GH-03)

20 репо — deploy keys: 0, прямые соавторы: только владелец, вебхуки: 0,
Actions-секреты: 0. Аномалий нет. Поле `two_factor_authentication`
fine-grained токен не отдаёт — истина в браузере: если 2FA выключена, в
`Settings → Password and authentication` висит жёлтая плашка Enable
two-factor authentication с пометкой critical. SSH/GPG-ключи профиля и
Authorized OAuth Apps API не отдаёт — глянуть руками: там должно быть
пусто.
