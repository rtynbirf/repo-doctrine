# 05 · АВАРИЙНЫЕ ПРОЦЕДУРЫ

Каждая процедура — короткий чек-лист «делай по шагам, не импровизируй».
Эскалация всегда одна: Хозяин.

---

## 1. Токен протух / потерян

1. Выпустить новый по `03-токены-и-секреты.md` (права — минимум под задачу).
2. Обновить локальный файл с токеном, старый удалить.
3. Если старый где-то мог остаться (CI, чужая машина) — Revoke старого
   в `Settings → Developer settings → Fine-grained tokens`.

## 2. Токен утёк (чат, скриншот, коммит, лог)

1. **Revoke немедленно** — до расследования.
2. Аудит `Settings → Security log`: входы и действия за период компрометации.
3. Проверить `Deploy keys` во всех репо, `Authorized OAuth Apps`, `Collaborators`.
4. Выпустить новый токен, узкие права, короткий срок.
5. Если утёк в коммит — даже после удаления файла история хранит строку:
   токен отзвать обязательно; чистить историю (filter-repo) — только по
   решению Хозяина.
6. Записать в ворклог суть без самой строки токена.

## 3. Сломан main (плохой коммит / чужой force-push)

1. `git fetch origin` и посмотреть, куда ушла ветка:
   `git log --oneline origin/main -5`
2. Плохой коммит жив в истории → `git revert <sha>` → пуш. История чистая,
   ничего не переписывается.
3. Историю кто-то переписал (force-push) → восстановить из локального клона:
   ```bash
   git checkout -b restore-main <последний-хороший-sha>
   git push origin restore-main:main   # если это запрещено защитой — Хозяин решает
   ```
4. После восстановления — включить/проверить защиту ветки (см. `02-ветки-и-защита.md`).
5. Разбор в ворклоге: как попало, кто, как не повторить.

## 4. Репо удалено

- GitHub хранит удалённые репо **90 дней**.
- Восстановление: аккаунт → `Settings → Repositories → Deleted repositories`
  → Restore. (На аккаунте это лежит в профиле: `Settings → Repositories`,
  внизу раздел Deleted repositories.)
- После восстановления проверить: защиту ветки, topics, коллабораторов,
  Pages — некоторые флаги не восстанавливаются автоматически.

## 5. Взлом аккаунта (признаки: чужие входы, репо, ключи)

1. `Settings → Password` — сменить пароль немедленно.
2. `Settings → Sessions` — Sign out everywhere.
3. `Developer settings` — **отозвать ВСЕ токены** (personal access tokens),
   затем перевыпустить нужные.
4. `Applications → Authorized OAuth Apps` — отозвать незнакомые.
5. `Settings → Security log` — зафиксировать объём ущерба (что создано/удалено).
6. Включить/проверить **2FA** (`Settings → Password and authentication`) —
   на 2026-11-01 в аккаунте 2FA отмечено как не включённая: **включить**.
7. Проверить каждый репо: deploy keys, вебхуки, Actions-секреты.
8. Отчёт Хозяину с хронологией.

## 6. Локальный клон разошёлся с origin

```bash
git fetch origin
git status                    # кто впереди
git rebase origin/main        # если локальные коммиты твои
# или
git merge origin/main         # если история общая
# крайний случай (только ЛОКАЛЬНАЯ копия, не origin!):
git reset --hard origin/main
```

`reset --hard` по origin — допустим только когда локальные изменения не нужны.
Это единственный законный force-инструмент, потому что он бьёт по себе.

## 7. Универсальный порядок при ЛЮБОЙ аварии

1. **Остановить распространение** (revoke / не пушить / заморозить пуши).
2. **Зафиксировать факты** (скриншот, логи, sha) — до исправления.
3. **Исправить** по процедуре выше.
4. **Записать в ворклог**: что случилось, корень, сделано, урок.
5. **Закрыть дыру в доктрине**: если процедуры не хватило — дописать её.
