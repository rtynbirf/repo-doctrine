## Сингулярный ход (кратко)

Иммунитет двухслойный и не покупается — он выращивается:

1. **Внешняя граница (публичные):** rulesets на default-ветку — запрет force-push и удалений. Бесплатно, ставится API. Required-checks подключаются поэтапно, после стабилизации зелёного — как в карте.
2. **Внутренняя дисциплина (приватные ×15, 403-реальность free):** страж-маяк — CI-страж «прямой пуш в main без ДПР = 🔴 прогон-маяк» + чек-лист доктрины. Один универсальный YAML, размножаемый sha-fast-forward.

## Слой 1 · публичные rulesets (готовые команды к следующему прогону)

На каждый публичный репо аккаунта (по ревизии 08.11 из issue #17: rulesets 24 на 22, цель 26/26):

```bash
curl -X PUT \
  -H "Authorization: Bearer $GITHUB_TOKEN" \
  -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/rtynbirf/<REPO>/rulesets \
  -d '{
    "name": "wave3-immunity-default",
    "target": "branch",
    "enforcement": "active",
    "conditions": {"ref_name": {"include": ["~DEFAULT_BRANCH"], "exclude": []}},
    "rules": [{"type": "deletion"}, {"type": "non_fast_forward"}]
  }'
```

- `deletion` + `non_fast_forward` = запрет удалений и force-push — минимальный бесплатный канон (сверено с практиками из issue #17: rulesets как guardrails, замена branch protection).
- Проверка покрытия после волны: `GET /repos/rtynbirf/<REPO>/rulesets` на каждом публичном — счётчик в отчёте стража. Число 26 берётся из живого ответа API, не из головы.
- Required-checks: отдельный этап, когда конвейер стабильно зелёный (см. `12-свод-недоделок-2026-11-08.md`).

## Слой 2 · приватные: страж-маяк (заложен этим коммитом)

Файл: `.github/workflows/wave3-immunity-sentry.yml` (этот же коммит, аддитивно).

- Триггер: `push` в `main` + `workflow_dispatch` (самопроверка конфигурации).
- Логика: слияние ДПР (`Merge pull request…`/`Merge branch…`) — 🟢; автор в белом списке (`dependabot[bot]`, `github-actions[bot]`, `web-flow`, + репо-переменная `WAVE3_ALLOW_DIRECT`) — 🟢; иначе 🔴 падение с отчётом в лог и job summary.
- Режимы: `strict` (по умолчанию) — краснеет; `observe` — репо-переменная `WAVE3_SENTRY_STRICT=false`, только докладывает. Начинать можно с observe, ужесточать решением роя.

### Размножение sha-fast-forward

Файл копируется байт-в-байт (содержимое == sha файла-эталона) в `.github/workflows/wave3-immunity-sentry.yml` каждого приватного репо одним append-коммитом волны. Правки только через эталон в repo-doctrine, дальше повторное копирование.
