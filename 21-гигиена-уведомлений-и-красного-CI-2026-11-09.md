## 0. Зачем файл

Красный CI и хвост уведомлений — не «чужая погода» и не шум: это незакрытая
работа, оставленная на территории. Каждый красный latest-прогон — чужой агент
тратит время на разбор того, что мог закрыть автор пуша. Каждый непрочитанный
тред — задание, закопанное в очереди (грабля №41: инбокс копится хвостом,
а верхняя пятидесятка маскирует глубину). Здесь пять принципов гигиены —
дополнение к 12 законам §2 файла 20, не замена.

## 1. Красный CI — свой долг

Пуш, покрасивший воркфлоу, остаётся ответственностью автора до зелёного.
Протокол один: воспроизведи красный локально (тот же make/скрипт, что у гейта) →
патч → коммит → живой зелёный прогон, сверенный по API (run-id + `conclusion:
success`; «запушил» ≠ «запушилось», закон №12(а)). Уход от территории (следующая
волна, другой аккаунт, отчёт Хозяину) допустим только при **0 красных
latest-прогонов по своей репо**: по каждому воркфлоу берётся последний прогон
на актуальном HEAD, ключ дедупа — `path` воркфлоу (грабля №41: счёт ведётся
по фактам API постранично, не по памяти и не по верхней странице).

## 2. Манифесты в одном коммите

Каждый новый или изменённый файл регистрируется во **всех** реестрах-манифестах
репо тем же коммитом, где он появился: `REUSE.toml`, `MANIFEST_SHA256.txt`
(единственный законный способ его менять — `make manifest`),
portability-allowlist, геном (`cell-swarm/swarm.json`; в этом репо —
`swarm-doctrine.json`). Что из этого живёт в конкретном репо — видно по его
Makefile и гейтам; незнание состава реестров не оправдание, состав проверяется
до пуша (касание №5: новый файл сначала `git add`, потом `make manifest` —
манифест видит только отслеженное, грабля №40). Гейт T17 не должен ловить
дрейф: сработавший гейт — не победа пломбы, а признак незакрытой работы автора.
Дрейф = незакрытая работа.

## 3. Уведомления — тред = задание

Завершая работу, агент зачищает свои треды GitHub-уведомлений:
`DELETE /notifications/threads/{id}` (помечает тред прочитанным, хвост не копится
— грабля №41). Непрочитанных тредов на своём аккаунте не оставляем. Треды
CheckSuite от зелёных и устаревших прогонов помечаются прочитанным сразу:
уведомление — не журнал, а очередь заданий. Журнал — `worklog.md`, очередь —
инбокс. В конце сессии очередь пуста (закон №12(в), касание №11).

## 4. Честный красный

Если красный неустраним твоими руками — нужны секреты, сеть, внешний сервис,
права, которых у агента нет — агент обязан оставить в реестре работы
(`rtynbirf/github-runbook#10`) честный хвост: диагноз, ссылка на прогон,
что именно нужно Хозяину для зелёного. Молча уйти от живого красного —
хуже, чем не начинать: следующий агент платит за разбор из своего бюджета.
Зелёная ложь (disable воркфлоу ради тишины) запрещена законом №12(г) —
честный красный лучше зелёной лжи.

## 5. Пуш-гигиена

Перед пушем — `git pull --rebase origin main` (гонка волн — твоя
ответственность, закон №10). Force-push запрещён всегда: откат — только
`git revert` (README, правило 6; `02-ветки-и-защита.md`). При отказе пуша
`GH013` (ruleset, защита ветки) — пуш owner-PAT с bypass admin по процедуре
`03-токены-и-секреты.md` либо PR-флоу; красный пуш не бросается — работает
принцип 1.

## 6. Машинная приёмка

- **Свежий манифест:** `make manifest-check` локально после `git add` —
  до коммита, не после красного гейта.
- **Ноль красных latest-прогонов:** по каждому `path` — последний прогон
  на HEAD, `conclusion: success`, сверка через API
  (`GET /repos/{owner}/{repo}/actions/workflows/{path}/runs?per_page=1`).
- **Чистый инбокс:** `GET /notifications?per_page=50` постранично до нуля,
  свои треды сняты `DELETE /notifications/threads/{id}`.
- **Честный хвост:** для неустранимого красного — запись в
  `github-runbook#10` с диагнозом и run-id.
- **Пуш:** `git pull --rebase` до пуша, `ls-remote` после — HEAD совпадает.
