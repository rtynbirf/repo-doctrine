# ДОКТРИНА РЕПОЗИТОРИЕВ — человеком для человека

Приватная доктрина аккаунта `rtynbirf`. Написана 2026-11-01 по мандату Хозяина.
Задача доктрины одна: чтобы **любой** — Хозяин или агент — за 15 минут понимал,
как тут всё устроено, где что лежит и какие правила игры.

---

## ЕСЛИ ТЫ АГЕНТ И ЧИТАЕШЬ ЭТО — НАЧНИ ОТСЮДА

1. Аккаунт **общий**: на нём работают несколько агентов. Ты не один.
2. Твоя орбита указана Хозяином в мандате. Чужие репозитории **не трогать**:
   ни код, ни описания, ни настройки. Смотри карту: `06-карта-аккаунта.md`.
3. Правило аддитивности: добавлять можно, удалять и переписывать историю — нельзя.
4. Секреты (токены, ключи) живут **только** в локальных файлах вне git-слежки.
   Токен, побывавший в чате или скриншоте, считается скомпрометированным —
   см. `03-токены-и-секреты.md`.
5. Главный журнал операций — `rtynbirf/H-PE11-PHOENIX/worklog.md`.
   Сделал дело — записай. Формат: `04-конвенции-агентов.md`.
6. Устав на жизнь репозитория: **добавляй так, чтобы не пришлось откатывать**.
   Если пришлось — откатывай через `git revert`, НИКОГДА через force-push.
7. **Шаг 0 — реестр косяков.** Прежде первой операции мандата прочти целиком
   `22-реестр-косяков-агента-и-выводы-2026-11-09.md` и §2–§3
   `20-грабли-и-золотая-середина-агентов-2026-11-09.md`. Свои косяки сессии
   допиши в реестр до закрытия: DONE без записи косяков — фальшивый DONE.
   Полный закон: `26-канон-косяков-2026-11-11.md`.

## ТРИ ИСТОЧНИКА (зачем три типа репо)

| Источник | Что хранит | Природа |
|---|---|---|
| **Репозитории кода** (cell65-host и др.) | Инструкции: скрипты, конфиги, доки | Повторяемое: любой может запустить и получить закономерный результат |
| **Ворклог** (H-PE11-PHOENIX) | Журнал операций TH-* | Неповторимое: что случилось, почему, какой урок. Результат нельзя переиграть — его можно только записать |
| **Доктрина** (этот репо) | Правила игры | Как настраивать, как работать, что делать при аварии |

Инструкция переживает всех: алгоритм не стареет, пока его выполняют.
Результат первого прогона не вернёшь никому — поэтому он идёт в ворклог.

## СОСТОЯНИЕ НА 2026-11-01 (что уже сделано мандатом)

Настроено API по всем 17 репо (кроме двух архивов — они read-only):

- **все публичные репо:** защита default-ветки (force-push запрещён, удаление
  ветки запрещено, прямые пуши разрешены), secret scanning + push protection,
  Dependabot-алерты + автоматические исправления;
- **все репо:** merge-гигиена (squash по умолчанию, rebase выключен, авто-merge,
  авто-удаление веток после merge, авто-обновление ветки);
- **наши операционные (cell65-host, H-PE11-PHOENIX):** обновлены описания,
  выставлены topics, выключены неиспользуемые Wiki/Projects/Discussions;
- **на все приватные не-архивные репо (6 шт.) поставлен guardian-tripwire:**
  детекторы force-push и секретов на Actions — бесплатная компенсация
  отсутствия Pro (см. главу 02, «Компенсирующий контроль»);
- **создан этот приватный репо** `repo-doctrine` с полной доктриной.

Чего НЕЛЬЗЯ сделать на бесплатном плане (записано в `02-ветки-и-защита.md`):
защита веток на **приватных** репо и secret scanning на **приватных** репо —
нужен GitHub Pro или Advanced Security. Как только появится Pro — включается
по чек-листу за 10 минут.

## БЫСТРЫЙ СТАРТ: НОВОЕ РЕПО ЗА 15 МИНУТ

1. Создай репо (без Wiki/Projects, с README).
2. Описание человеком: «что это, для кого, чем отличается от соседей».
3. Topics 5–15 штук (About → шестерёнка).
4. Флаги из `01-чеклист-настроек.md` (таблица, раздел «Pull Requests» + «Features»).
5. Защита default-ветки из `02-ветки-и-защита.md` (публичное — сразу; приватное — при Pro).
6. Secret scanning + Dependabot (раздел «Security» того же чек-листа).
7. Если токен нового агента — выдай по правилам `03-токены-и-секреты.md`.
8. Добавь репо в карту `06-карта-аккаунта.md`.

  заморозки — граница объявлена в шапке манифеста. Скрипт: `scripts/manifest_check.py`. Issue: repo-doctrine#24.

## ИСПОЛНЯЕМОЕ ПРИЛОЖЕНИЕ ДОКТРИНЫ: РИТУАЛ КАК АВТОМАТ

Правило «поработал → сделал → убрал за собой» существует не только текстом — оно
исполняется машиной: **[`domovoy-ritual`](https://github.com/rtynbirf/domovoy-ritual)**.

| Что | Где |
|---|---|
| Устав: аксиомы A1–A7, FSM `M=(S,Σ,δ,s₀,F)`, guard-ы G1–G7, 12 дефолтов «всё решаю сам», инварианты дома H1–H5 | `RITUAL-FSM.md` |
| Исполняемый автомат (stdlib-only): такт `enter → work → verify → seal → clean → status`, аварийная ветка `abort → recover` | `house_fsm.py` |

Сеанс агента = такт автомата: детерминированные переходы, REJECTED вместо исключений,
машинные свидетельства (SHA, коды), пломбы SHA256, токены стёрты к концу такта (G6).
Конвенция `04-конвенции-агентов.md` получает исполняемую форму — агент, вступивший в дом,
исполняет такт вместо того, чтобы помнить правила.
